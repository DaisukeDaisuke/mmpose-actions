# RTMW3D WebGPU ONNX builds
足首・足先を含む全身カメラトラッキング向けに、RTMW3D-L / Xの容量・推論コスト・量子化による関節変化を比較できるONNXをGitHub Actionsで作成する。全候補が133点と相対Zを保持する。顔だけ・手だけのモデルは含めない。
元モデル・実装: https://github.com/open-mmlab/mmpose
公開先: https://huggingface.co/RabbitDaisuke/rtmw3d-webgpu-onnx
## 利点
同じ入力・出力契約で、軽いLと基準のX、FP32 / FP16 / INT8を比較できる。量子化するネットワーク内部の領域を変え、速度と全身・腰・膝・足首・足先の変化を個別に評価できる。FP16やINT8が高速だと決めつけず、採用前にGPUで測れる。
SimCC復号をONNX内に含め、出力を1,021,440 bytesから2,128 bytesへ減らす。元モデルの全133関節は削らず、GPUからブラウザ側へ戻す量だけを減らす。容量、SHA-256、量子化対象ノード一覧と検証結果を同梱する。
## 比較する16候補
L / Xそれぞれで、FP32基準、FP16全体、FP16特徴抽出部、FP16特徴統合・全関節出力部、INT8全体、INT8特徴抽出部、INT8特徴統合部、INT8全関節出力部を作る。
`backbone`は特徴抽出部、`neck`は多段特徴の統合部、`head`は全133関節の出力部を意味する。人体の首・頭や顔だけへの限定ではない。INT8は指定したConv / MatMul / Gemm層のQDQ量子化である。
## Actions
mainへのpushまたは手動実行で動く。公式チェックポイントからL / Xを並列エクスポートし、12個の追加量子化ジョブを最大12並列で実行する。PyTorchとのFP32比較、ONNX検査、同じ検証入力に対する関節変化を検査し、全成果物を組み立ててからHF_TOKENで公開する。PRではHubへ送信しない。HF_TOKENはActions secretだけで使い、ファイルやログへ出さない。
## 評価の範囲
校正用と検証用の画像IDは重複させない。CPU結果は小さい画像セットによる変換検査であり、COCO / H3WB全体の精度評価、歩行動画の時間安定性、1〜4実カメラの同期・統合の実測ではない。足首・足先を独立して比較し、顔の点数で全身の劣化を平均化しない。
CPUでのFP16比較はFP16へ丸めた重み・定数をFP32演算する参照検査で、ネイティブFP16の活性値丸めやWebGPUシェーダーの正しさを検証したことにはしない。GPU速度は同梱のbenchmarkで同じローカル動画から実測する。1〜4入力相当の時分割負荷も分けて測り、合計fpsを各カメラのfpsと混同しない。
Zは骨盤相対であり、人物の絶対距離ではない。1〜4視点の全身追跡に使う際は、ROIの元画像座標への逆変換、校正、時刻同期、絶対位置推定・統合を別途行う。
## パッチ済みランタイム
添付のパッチをそのまま保持し、ONNX Runtime Web 1.27.0のJSEP WebGPUを含むort.all.min.mjsへ適用する。行列積の累積をFP32へ変更する。置換箇所数、完全適用、再適用時の同一性を検査し、対応するJSEP WASMと同じ版で配布する。別バックエンドのort.webgpu.min.mjsへ一致しないパッチを当てたと偽らない。
ソースは既存のMITライセンスに従い、配布する公式モデルは元のApache-2.0を付ける。出典とチェックポイントURLをレポートへ記録する。
## 実行経路とモデルの比較
同じFP32モデルのGPUメモリ再利用・NHWC・Graph Capture・パッチ前後を比較し、別セッションでGPU演算別時間を記録する。MediaPipe Pose / Holisticの比較と、同じ入力でのネイティブGPU診断も用意する。詳細は[比較手順とモデル判断](benchmark/README.md)を参照する。ベンチマークだけの更新は専用Actionsで検証・公開し、モデルの再エクスポートを必要としない。
実測で時間を占めた2つの出力直前の畳み込みについて、同じFP32重みの明示的im2col＋行列積と、8分割した積の和を比較する実験を`experiments/`に用意する。学習・量子化・関節削減を行わず、133点の相対3D出力を維持する。専用Actionsの2並列ビルドで、パディング・ストライド・dilation・分割和と、公開人物画像による全身・足の出力差を検査してからHFへ公開する。実GPUでの高速化はCPU変換検査と分けて確認する。
